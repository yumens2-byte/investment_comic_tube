# 대본 사실 게이트 품질 개선 v1 (P1·P2) — 2026-10-03

## 배경 (운영 DB 사실)

- Ep.31(10/01)·Ep.32(10/02): `status=published_degraded`, `degraded_reason=story:malformed_response`.
- `pipeline_slots.counts.text:storyboard=2`: 첫 생성과 재시도가 모두 `market_facts.resolve`에서 거부됐다.
- 발행 대본은 안전 모드 폴백 6문장(7~13자)이었다. 렌더 하한(훅 3.0초 + 본문 5×3.5초 + 아웃트로 2.0초 = 22.5초) 근처로 렌더됐다.
- 폴백 마지막 문장 `다음 시장 신호를 기다린다`가 `story_state.unresolved`로 저장되어 다음 회차 프롬프트에 들어갔다.

## 원인 (코드)

1. 프롬프트가 원시 수치를 주면서 "수치 두 개를 비교하라"고 지시했다. 끝에 붙은 계약은 숫자를 쓰지 말라고 했다.
2. 이전 회차 맥락에 원시 숫자(직전 X → 오늘 Y)와 숫자가 든 이전 문장이 들어갔다.
3. 토큰 밖 상승·하락·급등·급락은 모두 거부됐다.
4. 숫자 정규식이 오탐했다: `구원자`, `영원한`, `구원의`, 지표명 `10년물`, `S&P 500`.
5. 문장 하나만 실패해도 전체를 재생성했고, 2회 실패하면 폴백을 그대로 발행했다.

## 운영 영향

- 안전 모드에서 대본이 최종 실패하면 해당 날짜는 **발행하지 않는다**(fail-closed). 같은 날 재실행하면 `text:polish`(1회)와 `text:storyboard`(2회) 한도가 이미 소진된 상태다. 따라서 `operational_recovery.py grant-extra`로 두 asset 모두 추가 시도를 받아야 한다. 단계별 일일 추가 상한은 총 2회(SQL `override`)이므로, 재실행에서 대본 호출은 사실상 1회(수정 호출 없음)다. 안전 모드에서 polish 결과는 토큰을 포함할 때만 쓰이고 그 외에는 storyboard 1번 문장으로 대체된다(`director.py`). 이 호출을 생략하면 이 제약이 줄어든다(이번 범위 밖, 별도 승인 필요).
- 남은 위험: 토큰 밖 방향어(예: 하락장)의 의미 정합성은 프롬프트의 방향 사실로만 유도한다. 결정론적으로 검사하지는 않는다. `한 배를 탄` 같은 고유어 숫자 + 배 관용구는 계속 거부된다.
- 실제 Gemini 응답의 통과율과 영상 길이는 운영 실행으로 검증해야 한다(이 환경에는 API 키가 없다).
